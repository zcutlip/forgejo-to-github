## Summary

Audit found 2 critical, 3 medium, and 2 minor findings. All findings are test-strength issues (tests that can pass while the guarded behavior is broken), not production-code defects. No implementation changes are proposed here.

## Findings

### CRITICAL

#### 1. Import-side-effect tests never exercise a fresh import — `tests/test_package_boundaries.py:92–133`

- **Issue:** Both import-side-effect tests call `importlib.import_module` after collection already imported the package. The import cache (`sys.modules`) prevents a fresh import, so imports could perform network/subprocess side effects and the tests would still pass.
- **Recommendation:** Run the import in a fresh subprocess with restrictions in place before the import (e.g. subprocess that blocks network/subprocess and then imports), rather than `importlib.import_module` in-process.

#### 2. Clone-cleanup tests assert cleanup of a path that was never created — `tests/test_git_service.py:993–1068`

- **Issue:** 3 clone-cleanup tests use a fake runner that raises before creating the destination directory. Assertions that the absent path is gone always pass without exercising any cleanup code.
- **Recommendation:** Create a partial destination path before the raise (as the cache test does), so the cleanup assertion verifies removal of something that actually exists.

### MEDIUM

#### 3. Clone-vs-API ordering comparison uses incomparable indices — `tests/test_orchestration.py:336–355`, `tests/test_orchestration.py:427–475`

- **Issue:** Clone and API calls are recorded in separate lists. At 427–475, indices from `api.calls` and `state.events` are compared as if they establish ordering, but positions in two independent lists cannot establish relative order.
- **Recommendation:** Record both kinds of events on a shared event timeline (single ordered log) and assert ordering against that timeline.

#### 4. fsync durability test does not verify rename-before-directory-fsync — `tests/test_state_store.py:361–380`

- **Issue:** The fsync test asserts durability but does not check that the rename happens before the directory fsync, leaving the critical ordering unverified.
- **Recommendation:** Use a shared order recorder that includes `os.replace` alongside the fsync calls, and assert the rename precedes the directory fsync.

#### 5. Read-only-directory test is privilege-dependent — `tests/test_state_store.py:271–281`

- **Issue:** `chmod` to `0o500` is privilege-dependent; a privileged runner (e.g. root) can still write into the read-only directory, so the expected failure may not occur.
- **Recommendation:** Replace the chmod-based setup with a mocked write/probe failure (mock the write or probe to raise), making the failure deterministic regardless of privileges.

### MINOR

#### 6. Failed-count assertion can match an unrelated '1' — `tests/test_reporting.py:158–178`

- **Issue:** The test only looks for a plain `'1'` in the output, so a `'1'` appearing anywhere (unrelated count, version, timestamp fragment) could satisfy the failed-count check.
- **Recommendation:** Assert the labeled failed counter (the specific label + value pair), not a bare `'1'`.

#### 7. Ahead-exclusion check permits the secret branch through — `tests/test_cwd_freshness.py:495–516`

- **Issue:** The ahead exclusion uses `any('secret-branch' not in entry for entry in result.ahead)`, which passes if any single entry lacks the secret branch — letting the secret branch through whenever another entry exists.
- **Recommendation:** Assert that none of the entries contain it (e.g. `all('secret-branch' not in entry ...)` or `not any('secret-branch' in entry ...)`).
