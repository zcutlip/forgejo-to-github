## Findings

### Critical

1. **Dependency guard covers 1 of the 3 load-bearing scripts; fixture copies unchecked.**
   The proven guard pattern (`COMMAND_PRESENT` at lines 387–393 + `run_test` at 395–409 — empirical result: 0/45 passes) is applied only to `src/issue-branch`. `src/functions.sh` and `src/read_about_version.py` have no guard of any kind. `make_project` (lines 235–238) and `rich_project` (lines 321–324) `cp` all four scripts with no status check: missing files fail silently (baseline log contains 40 `cp:` error lines), and the suite proceeds against a broken fixture. `write_about_version.py` is guarded only inside the 6 unit tests via `assert_exists`.
   - Impact: 13–22 of 45 tests report green with a missing dependency; failures that do appear are misattributed to contracts rather than to the broken fixture.
2. **Rejection assertions cannot discriminate *why* the command failed** *(13 tests, listed above; root cause of the hard-vacuous class)*.
   - The suite's own best practice exists and demonstrably discriminates: `test_finish_rejects_untracked_files` asserts the output names `notes.txt` (line 622) — and it correctly *failed* in the `functions.sh` scenario because the source error output does not contain it. `test_create_rejects_existing_branch`'s positive control ("first create succeeds", lines 453–455) likewise kept it failing there. Most rejection tests have neither a message assertion nor a positive control.

### Medium

3. **`test_status_is_non_mutating` asserts a label, not a value** (line 554: `assert_contains "status reports current version" "Current version:"`). Empirically passed in the `read_about_version.py` scenario with an empty version behind the label (`cmd_status` prints `Current version: $ib_ver` with `ib_ver=""` — `src/issue-branch` line 406). All seven non-mutation assertions then hold trivially.

### Minor

4. **Leftover `set -x` / `set +x` debug** in `test_write_script_rejects_missing_assignment` (lines 1116–1121) — traces the python invocation on every run.
5. **40 `cp:` error lines per run** — the anticipatory fixture copy of the not-yet-existing `src/write_about_version.py` fails unchecked on every `make_project`/`rich_project` call. Noise that buries real signals in the RED output.

## Context Notes

- The RED-by-design shape is currently disclosed in the right place: unit tests (`assert_exists`), with integration tests legitimately green for the contracts the current implementation satisfies.
- Platform caveat: the 13-test vacuous pass depends on the source-failure exit status of the platform's `/bin/sh` matching the expected `1`. On shells where `.` failure exits 2 or 127, `assert_status` would reject it — the vacuous surface is partially platform-dependent, which is itself a reason the guard gap matters.
- The silently-empty `current_version` at HEAD is a latent implementation defect (`quit` inside `$( )` only exits the subshell); its observable test-side consequence is the 9-pass subclass above and finding 3.
- Coverage: this suite exercises `issue-branch` only. `deletebranch`, `gc_about`, `gc_changelog`, `release`, `tag` have no tests — outside this audit's scope, noted for completeness. (Coverage analysis not otherwise performed — opt-in feature.)
