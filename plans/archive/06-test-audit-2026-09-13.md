## Findings by Severity

### Critical Issues (Must Fix)

**1. Vacuous token-leak assertion — `or True` kills the check** — `tests/test_repository_description.py:261` (`test_codeberg_metadata_transport_exception_raises_transport_error`)

```python
assert "tok" not in str(excinfo.value) or "<redacted>" in str(excinfo.value) or True
```

- **Impact:** The trailing `or True` makes this tautological — the test passes even if the client leaks the token. This is a security-redaction contract, and it is currently unenforced at this boundary. Compounding: `"tok"` is a weak 3-char sentinel (compare the robust `"super-secret-token"` pattern in `test_codeberg_client.py::test_transport_error_does_not_leak_token`, which asserts correctly).
- **Recommendation:** Replace with the sibling pattern, reopened via RED per project workflow:

  ```python
  assert "tok" not in str(excinfo.value)
  ```

  Optionally strengthen the fixture token to `"super-secret-token"` for sentinel distinctiveness.

**2. Vacuous loop is the sole assertion** — `tests/test_git_service.py:661` (`test_url_token_is_redacted_in_logged_command`)

```python
for record in caplog.records:
    assert TOKEN_SENTINEL not in record.getMessage(), ...
```

- **Impact:** If `GitMirror.push_branches` ever stops logging at INFO, `caplog.records` is empty, the loop body never executes, and this redaction test passes having asserted nothing. There is also no positive control: nothing proves a token-shaped URL was actually emitted and scrubbed, so "redaction works" is indistinguishable from "nothing was logged."
- **Recommendation:** Add a non-empty guard plus a positive redaction witness (the pattern already exists in `test_clone_stderr_token_is_redacted_in_error_text`):

  ```python
  assert caplog.records, "expected push command lines to be logged"
  for record in caplog.records:
      assert TOKEN_SENTINEL not in record.getMessage()
  assert any(REDACTED_PLACEHOLDER in r.getMessage() for r in caplog.records)
  ```

### Medium Issues (Should Fix)

**1. Failure-count assertion cannot fail** *(highest impact in tier)* — `tests/test_reporting.py:207` (`test_report_names_every_failure_exactly_once`)

```python
assert text.count("3") >= 1
```

- **Impact:** The fixture already contains `issues_attempted: 3`, so `"3"` appears in the summary regardless of whether the *failure* count is ever rendered. The truthfulness contract named in the docstring ("must expose a structured failure count … equal to the input") is unverified.
- **Recommendation:** Assert the labeled count instead, e.g. `assert "3 failed" in text` (or whatever the Issues line's exact rendering is).

**2. Weak `or` chain — failure-number naming unverified** — `tests/test_migration_reporting.py:373` (`test_issue_failure_is_accumulated_and_later_issues_continue`)

```python
assert "CB #1" in combined or "CB # 1" in combined or "1" in combined
```

- **Impact:** The final disjunct `"1" in combined` is satisfied by any count digit (`1 failed`, `1 succeeded`), so the test passes even if the summary never names CB #1.
- **Recommendation:** Drop the bare-`"1"` disjunct; keep the two `"CB #1"` spellings, or assert the exact known format only.

**3. Grouped: RED-era parent-class escape hatches** *(4 tests)* — `tests/test_git_service.py`

- Affected: `test_clone_nonzero_exit_raises_structured_git_clone_error` (line 253, `or isinstance(exc, SystemExit)`), `test_clone_auth_failure_is_classified_as_git_auth_error` (line 301, `or "GitCloneError" in cls_name`), `test_clone_timeout_classified_as_git_clone_timeout_error` (line 334, `or "GitCloneError" in cls_name`), `test_branch_push_non_fast_forward_is_classified_with_advice` (line 528, `or "GitPushError" in cls_name`).
- **Impact:** Each second disjunct is a *parent* class (or SystemExit), so a misclassified error still passes — the classification contract named in each docstring ("classified as GitAuthError" etc.) is not what these lines enforce. **Mitigation:** strict equivalents exist (`test_git_errors.py` asserts `GitAuthError` and `GitPushRejectedError` via `pytest.raises`; `test_clone_timeout_removes_tempdir_before_raising` asserts `"Timeout"` in the type name), so this is misleading rather than a coverage gap.
- **Recommendation:** Now that GREEN has settled the hierarchy, tighten to the exact class name (e.g. `assert "GitAuthError" in cls_name`) or delegate entirely to the strict `test_git_errors.py` siblings and drop the redundant checks.

**4. Weak `or` — repo name in 404 message** — `tests/test_api_clients.py:245` (`test_fetch_all_codeberg_issues_404_raises_not_found`)

```python
assert "owner/source" in str(exc_info.value) or exc_info.value.url != ""
```

- **Impact:** `url != ""` is satisfiable by any non-empty URL, so the "message names the repo" half is unverified.
- **Recommendation:** Split into two asserts: `assert "owner/source" in str(exc_info.value)` and `assert exc_info.value.url.endswith(...)`.

**5. Weak `or` — transport message content dead** *(lowest impact in tier)* — `tests/test_api_clients.py:257` (`test_fetch_all_codeberg_issues_connection_error_propagates_as_transport`)

```python
assert "Could not resolve" in str(exc_info.value) or isinstance(exc_info.value, CodebergTransportError)
```

- **Impact:** `isinstance` is already guaranteed by `pytest.raises(CodebergTransportError)`, so the message check never runs.
- **Recommendation:** Keep only `assert "Could not resolve" in str(exc_info.value)`.
